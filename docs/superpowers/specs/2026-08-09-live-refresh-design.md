# AI 晨报手机端实时更新设计

## 背景与目标

AI HOT 通常在北京时间 08:01 左右生成当日日报，但 GitHub Actions 的定时任务可能延迟数小时。现有首页只展示部署时写入的静态内容，因此手机在早晨打开时可能仍看到昨天的数据。

目标是让首页的新鲜度不再依赖 GitHub Actions 是否准时，同时继续保留静态页面作为断网和接口异常时的可靠回退。

## 方案

首页采用“实时数据优先、静态快照兜底”：

1. 生成器继续把最近一期 AI HOT 日报完整写入单文件 HTML。
2. 页面在首次加载、从后台返回及用户点击“检查更新”时，请求 AI HOT 最新日报接口。
3. 请求使用禁止浏览器缓存的选项。若接口返回的日报日期不早于页面内嵌日期，则用同一套五版块规则重新渲染 Hero、统计、导航、卡片和页脚。
4. 若请求失败或数据结构不合法，页面保留静态内容，不出现空白页。
5. GitHub Actions 继续负责每日归档和静态快照，但不再承担首页准时更新的唯一责任。

## 页面状态

Hero 下方增加一个紧凑的同步状态区和“检查更新”按钮：

- 检查中：正在检查最新日报。
- 成功：已同步今日日报，并显示北京时间。
- 已是最新：当前已是最新一期。
- 回退：实时更新失败，正在显示最近缓存；用户可以再次检查。

状态区沿用现有绿色、灰色和橙色体系，不增加外部资源；手机端按钮保持至少 42 像素触控高度。

## 数据与渲染规则

- 固定五版块：模型发布/更新、产品发布/更新、行业动态、论文研究、技巧与观点。
- 按上述顺序全局连续编号，不在版块内重置。
- 每张卡片继续包含标题、来源、最多 60 字中文摘要和安全的新窗口原文链接。
- 所有日期和时间转换为北京时间中文格式，不显示 ISO 字符串。
- 页面标题、描述、Hero 总数、五版块统计、导航计数和页脚总数必须同步更新。
- 历史归档页只显示其固定日期快照，不执行实时替换。

## 错误处理与安全

- AI HOT 已验证允许跨域访问；请求仍设置超时，避免弱网下长期停留在加载状态。
- 对接口返回值进行日期、版块和条目结构校验后再更新 DOM。
- 所有动态文本通过 DOM 文本节点写入；链接只允许 http: 或 https:，并保留 target="_blank" 与 rel="noopener noreferrer"。
- 页面初始化失败不影响已有静态导航和卡片阅读。

## 验证范围

自动化测试先复现“静态快照是昨天但接口已有今天”的场景，再验证：

- 页面包含实时检查逻辑和可见状态。
- 较新日报会替换全部动态区域。
- 同日数据不会破坏页面。
- 网络错误保留静态快照并显示回退状态。
- 五版块、全局编号、摘要长度和安全链接仍符合原要求。

发布后分别验证桌面和 390×844 手机视口，包括首次加载、手动检查更新、版块导航、无横向溢出、控制台无错误，并确认线上页面可直接同步当日 AI HOT 数据。
